# ax: Retro

프로젝트별 문서 목적지(함정 문서 경로, 인덱스 위치)는 리포 루트의 `.claude/ax.md`에 있다. **먼저 읽는다.**

## Overview
파이프라인을 닫으며 남길 만한 규칙을 뽑아, **다음 세션이 실제로 읽을 자리**에 쓴다.

**서브에이전트로 돌리지 않는다.** 이 스킬의 입력은 "이번 파이프라인에서 뭐가 어긋났나"라는 세션 이력 자체다. 격리하면 입력이 사라진다.

## 목적지 판단 — 이 스킬의 핵심

| 문서 | 로드 시점 | 여기 넣을 것 |
|---|---|---|
| `CLAUDE.md` | **매 세션 전량** | 몰랐다면 첫 시도부터 틀리는 것 (타깃/툴체인, 아키텍처 원칙, 금지, 워크플로) |
| 함정 문서 (`docs/gotchas.md` 등) | **그 증상을 만났을 때만** | 특정 API 함정, 특정 에러의 원인, 검증 기법 — 상황이 와야 쓸모 있는 것 |

**기본값은 함정 문서다. `CLAUDE.md` 추가는 예외다.**

이유 두 가지: (1) `CLAUDE.md`가 커질수록 정작 중요한 규칙이 묻힌다. (2) `CLAUDE.md`는 프롬프트 캐시 프리픽스에 들어가므로, 고칠 때마다 그 프로젝트의 **이후 모든 세션이 콜드 스타트**한다. 그러니 `CLAUDE.md` 수정은 드물게, 그리고 **PR 단위로 모아서 한 번에** 한다.

## When to Use
- `/ax:refresh-docs` 직후, 기능/PR이 끝났을 때.
- NOT: 매 태스크마다. 기능 단위로 한 번.

## 남길 가치가 있는 교훈
- **코드를 읽어선 알 수 없는 것** (함정, 타입 시스템에 안 담기는 제약, 반복된 실수).
- **지속되는 것** — 다음 기능에도 적용된다. 이번 것에만 해당하면 버린다.

"이번에 뭘 만들었나"는 CHANGELOG의 몫이지 여기가 아니다.

## Workflow

1. 파이프라인을 되짚는다: 건너뛴 단계, 다시 한 단계, 마찰이 난 지점이 있었나? (plan 태스크가 알고 보니 `.pbxproj` 편집을 요구했다, spec이 플랫폼 제약을 놓쳤다, 다른 머신에서 테스트가 깨졌다 등)
2. 진짜 교훈마다 **한 줄 규칙**으로 쓴다. 이야기가 아니라 "X → Y 해라" 형식.
3. 목적지를 이 질문으로 고른다: **"다음 세션이 첫 행동을 하기 전에 이걸 몰라도 되는가?"**
   - 몰라도 된다(특정 상황에서만 필요) → 함정 문서. **기본값.**
   - 모르면 첫 시도부터 틀린다 → `CLAUDE.md`.
   - Git/PR 흐름 → 프로젝트의 워크플로우 문서.
4. 함정 문서에 **새 절**을 만들었으면 `CLAUDE.md`의 인덱스에 한 줄을 추가한다. 인덱스는 절 이름 나열이 아니라 **증상 문장**으로 쓴다 — "X가 안 됨 / Y 에러가 남 → 「절 이름」". 그래야 다음 세션이 그 상황에서 읽어야 함을 알아챈다. 미해결 제약은 "(미해결 제약, 우회책만 있음)"처럼 명시해 해결된 것으로 오해하지 않게 한다.
5. 경로는 **현재 작업 디렉터리에서 리포 루트를 resolve**해 쓴다 (`git rev-parse --show-toplevel`). 특정 체크아웃 경로를 하드코딩하지 않는다 — git worktree에서 작업 중이면 주 체크아웃과 디렉터리가 다르고, 엉뚱한 쪽을 고치면 아무도 안 보는 브랜치에 조용히 기록된다.
6. 교훈이 ax 스킬 자체에 대한 것이면(단계가 모호했다, 체크리스트 항목이 빠졌다) 해당 `SKILL.md`를 고친다. 단, **`description`은 건드리지 않는다** — description은 전역 프롬프트 캐시 프리픽스라, 한 글자만 바꿔도 모든 프로젝트가 콜드 스타트한다. 본문만 고친다.
   고친 뒤, 리포에 사본(`.claude/skills/ax/`)이 있으면 동기화해 같이 커밋한다:
   `rsync -a --delete --exclude README.md ~/.claude/skills/ax/ "$(git rev-parse --show-toplevel)/.claude/skills/ax/"`

## Common Mistakes
- 서술형 회고 문서를 새로 쓰기 — 이 스킬의 산출물은 **기존 파일에 대한 편집**이지 새 문서가 아니다.
- 다음 기능엔 안 중요할 프로젝트 잡지식 기록 — 미래 행동을 안 바꾸면 저장하지 않는다.
- 상황별 함정을 `CLAUDE.md`에 바로 append — 매 세션 로드량과 캐시 미스만 늘고 정작 중요한 규칙이 묻힌다.
- 함정 문서에만 적고 인덱스를 안 남기기 — 아무도 그 절을 열지 않아 같은 실수가 반복된다.
