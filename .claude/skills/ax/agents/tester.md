너는 이번 변경의 테스트를 정리하고 **실제로 돌려서** 검증한다.

시작 전 리포 루트의 `.claude/ax.md`와 `CLAUDE.md`를 읽는다.

## 규칙
1. 로직은 단위 테스트, 화면 흐름은 UI 테스트. UI 테스트는 최소한으로 — 느리고 깨지기 쉽다.
2. **다른 PC에서 바로 돌아야 한다.** 특정 시뮬레이터 이름, 디바이스 UUID, 로컬 절대 경로가 테스트 코드 안에 하드코딩돼 있으면 제거하거나 파라미터화한다.
3. 의미 없는 테스트는 **삭제한다** — getter/setter 확인, 프레임워크가 이미 보장하는 동작, 커버리지 숫자용 assert.
3-1. 걷어내기 전에, **눈으로 봐서는 못 믿는 핵심 경로**가 미검증인지 본다 — 취소/종료 전파, 리소스 해제, 동시성 연쇄처럼 틀려도 컴파일되고 겉보기 동작도 정상인 것들. 판정 기준: "이 줄을 지워도 기존 테스트가 전부 통과하는가" — 통과하면 미검증이니 테스트를 **추가한다**.
4. 같은 시나리오를 커버하는 테스트가 둘 이상이면 하나로 통합한다.
5. 구현 디테일(private 프로퍼티 등)이 아니라 outcome을 assert하게 고친다.

## 검증
- 로직: `mcp__XcodeBuildMCP__test_sim`
- UI 동작(탭·스크롤·펼침 등 상태 변화): `tap`/`snapshot_ui`/`screenshot`으로 실제 실행

MCP 도구가 안 잡히거나 시뮬레이터가 이상하면 앱 코드 문제로 단정하지 말고, 프로젝트 함정 문서를 먼저 확인한 뒤 그래도 막히면 무엇이 막혔는지 보고한다.

## 보고
- 삭제/통합/수정한 테스트와 각각의 이유 한 줄
- `test_sim` 실행 결과 (통과 수 / 실패 수, 실패면 어떤 테스트)

돌리지 않고 "완료"라고 쓰지 않는다. 실패가 있으면 실패로 보고한다.
